Technical specification
Abide
A bilingual daily-devotion app for a church youth ministry: everyone walks the same study on the same day, in Amharic or English, offline, with streaks that reward showing up. This is the build contract — data model, rules, screens, and order of work.

Blocking gates
Two things can stop this app reaching users. Neither stops development. Both have long lead times, so both start now.
⬤
 Gate 1 — Scripture licensing
The bundled 
EnglishNIVBible.xml
 and 
AmharicNASVBible.xml
 are both © Biblica, Inc. (NIV; Amharic አዲሱ መደበኛ ትርጕም © 2001). Not open source — scraped from bible.com. The Amharic file carries the copyright notice in its own root element.
Development proceeds against them.
 Distribution does not. Nothing ships to a store, or to any user outside the dev team, until Biblica grants written permission. The ministry owns that request and should send it this week.
Engineering mitigation:
 the reader is built translation-agnostic. Translations are rows, not assumptions. If permission is refused, a public-domain text (KJV / WEB for English) drops in with no code change, and the Amharic side falls back to deep-linking YouVersion.
⬤
 Gate 2 — Font licensing
The prototype embeds 
Nokia Pure Headline
 and 
Nokia Ethiopic
 (Nokia's proprietary corporate typeface) and 
Niyala
 (ships with Windows; its EULA forbids app embedding). None are licensable for this.
Replacement:
 Noto Sans Ethiopic and Noto Serif Ethiopic (SIL OFL, full Ethiopic coverage) with Abyssinica SIL as an alternate. Metrics differ from the originals, so layouts shift — this must be resolved 
before
 design finalisation, not after.
◐
 Not a gate, but a long pole — iOS Screen Time
Distraction blocking on iOS needs Apple's 
com.apple.developer.family-controls
 entitlement: a request form, human review, several weeks, approval not guaranteed. Apply early. Android ships without it; iOS lights up when (if) it lands.
Explicitly not doing
The 
.zbl
 files are encrypted commercial Bible-app packages (
encrypted="true"
, obfuscated asset paths). Extracting text means circumventing a technical protection measure — a separate legal problem that a Biblica permission grant would not cure. Not used as a text source. Their plaintext 
manifest.bible
 supplied the 66-book Amharic name and chapter-count lexicon, which is a list of book titles and carries no such restriction.

The outbox

Ordered, idempotent, at-least-once. Every mutation carries a client-generated UUID so a retried write cannot double-apply. On flush the server returns authoritative state for anything it changed.

Build phases
Ordered so the licensing gates sit late and isolated. Phases 0–5 deliver a genuinely usable app with no dependency on either permission landing.
0
Foundations
Monorepo, shared TypeScript domain types, Supabase project, full schema with RLS policies written and tested, Expo app skeleton, Next.js admin skeleton, CI.
Done when:
 a test user can sign in on device and the RLS policy denying admin access to reflections has a passing test.
1
Content pipeline
Reference parser with chaining, validator against Bible text, JSON importer, summary-day synthesis, seed of all three supplied books.
Done when:
 Ruth, Psalms Pt.2 and 1 Timothy are in the database with every resolvable reference canonicalised and the six exceptions reported.
2
The core loop
Onboarding, Today, devotion detail, completion rule, streak engine with the repair-rule registry, streak screen with the Ethiopian calendar.
Done when:
 a user can complete a day, break a streak, backfill, and repair — and the server-side recomputation agrees with the client every time.
3
Offline &amp; sync
Local SQLite, delta pull, outbox, conflict resolution, clock-tamper validation.
Done when:
 airplane mode for a week then reconnect produces correct state, tested against a device with a deliberately wrong clock.
4
Library &amp; reflections
Devotions library with filters and search, book detail, favourites, Reflect tab, summary-day screen.
Done when:
 every path to a devotion works and future books are provably invisible.
5
Admin dashboard
Bilingual editor, import UI with pre-commit validation report, scheduling calendar in EC, review and publish flow, content strings, users.
Done when:
 the ministry can author and publish a book without an engineer.
6
Notifications
FCM, device registration, the full ladder as scheduled jobs, template management, broadcasts with targeting, per-user preferences, rate limiting.
Done when:
 every rung fires correctly in a simulated month and the two-per-day cap holds.

Focus &amp; prayer
Timer, presets, Android DND and screen pinning, leave-detection, prayer session history. iOS shielding if the entitlement has landed.

 DND engages and reliably restores, including on force-kill.

Character &amp; polish 
gate 2
Font replacement across all screens, mascot moves in Reanimated, time-of-day sky, dynamic app icons, empty and error states, accessibility pass.
Done when:
 no proprietary font remains in the bundle and the Amharic layouts survive the metric change.
10
Hardening &amp; launch
Analytics, Sentry, force-update, privacy policy, deletion path, store listings, beta with a small group from the ministry.
Done when:
 both gates are cleared in writing and a real cohort has run a full book end to end.
Phase 9 is deliberately last and deliberately large.
 Replacing the fonts changes every layout's metrics, so doing it before the screens exist means doing it twice. Doing it after the screens are built means one honest pass. The risk is that it gets squeezed — do not let it.

Three things I would watch
The streak backfill/repair distinction will confuse users before it confuses engineers.
 Two visually distinct ✓ states and clear copy at the moment of repair matter more than the mechanic itself.
Ministry-synced scheduling makes the admin a single point of failure.
 If nobody publishes the next book, every user hits "coming soon" simultaneously. Phase 5 should include a reminder to admins when a round is within three days of running out.
The content is thinner than the prototype's layout assumes.
